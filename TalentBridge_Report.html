Abstract / Executive Summary: Campus recruitment drives frequently rely on rigid keyword matching and arbitrary CGPA cutoffs. This introduces the "Keyword Trap" (rejecting qualified students for using synonymous terminology such as "NLP" instead of "Natural Language Processing") and the "Rejection Void" (generic rejections with zero diagnostic feedback). TalentBridge resolves these issues through a multi-stage AI pipeline: (1) domain acronym canonicalization, (2) dense semantic matching using Sentence Transformers (all-MiniLM-L6-v2), (3) supervised interview readiness classification over a 5-dimensional feature space, and (4) prescriptive gap remediation offering targeted courses and projects. On a held-out test set ($N=29$), the supervised Random Forest model achieved 93.10% accuracy and 100% recall (zero false negatives), ensuring qualified students are never mistakenly screened out.

2. Chapter I: Introduction & Context

1.1 Background: Higher education placement drives process thousands of engineering students against hundreds of corporate requisitions under tight deadlines. Traditional Applicant Tracking Systems (ATS) rely on exact string matching and linear CGPA cutoffs to manage volume.

1.2 Problem Statement:

  • The Keyword Trap: Lexical matching fails to recognize semantic equivalents (e.g., PyTorch vs. Deep Learning), penalizing students due to syntactic variations.
  • Linear Heuristic Screening: Rigid rules (if CGPA >= 8.0 AND exp >= 6 mos) discard self-taught builders who have outstanding capstone projects but lower GPAs.
  • The Rejection Void: Students receive generic rejections with zero diagnostic feedback, preventing strategic skill development.

1.3 Objectives of the Study (SMART Goals):

  • Attain $\ge 90\%$ semantic similarity across technical aliases and framework hierarchies.
  • Achieve 100.00% Recall on evaluation data, guaranteeing zero false negatives among qualified candidates.
  • Deliver $\ge 90\%$ accuracy and $\ge 85\%$ precision using an ensemble Random Forest classifier.
  • Automatically generate actionable project and coursework roadmaps for identified skill gaps.
  • Maintain sub-15ms cached response times on an interactive web dashboard.

3. Chapter II: Literature Review & Technical Study

2.1 Evolution of ATS: Early commercial ATS platforms relied on Boolean search strings. Research shows keyword screening rejects over 70% of qualified candidates due to vocabulary mismatches (Faliagka et al., 2012). Lexical TF-IDF treats synonyms as orthogonal vectors, while static Word2Vec representations struggle with contextual multi-word technical descriptions.

2.2 Sentence Transformers & SBERT: Reimers & Gurevych (2019) introduced Sentence-BERT, utilizing siamese networks to derive continuous sentence embeddings comparable via cosine distance. TalentBridge adopts all-MiniLM-L6-v2, mapping text into 384-dimensional dense vectors with low CPU latency.

4. Chapter III: Methodology & Architecture

TalentBridge operates across four decoupled layers: (1) Data Layer (SQLite & JSON), (2) NLP Engine (Canonical Alias Map & SBERT), (3) Decision Layer (5D Feature Extraction, Logistic Regression, Random Forest, Recommender), and (4) Delivery Layer (Clean White-Background Streamlit UI & FastAPI REST service).

Cosine Vector Similarity:   Sim(u, v) = (u · v) / (||u||₂ ||v||₂) = Σ (uᵢ · vᵢ)   [for unit vectors in ℝ³⁸⁴]

Multi-Tier Gating Thresholds:

  • Strong Equivalence (Sim ≥ 0.75) Confirmed match (e.g., PyTorch ↔ Deep Learning).
  • Interview Review (0.55 ≤ Sim < 0.75) Related domain; flagged for technical interviewer verification.
  • Missing Prerequisite (Sim < 0.55) Prerequisite not satisfied; routed to recommender.

The 5-Dimensional Interaction Feature Space (x):

  1. x₁ (Required Skill Coverage): Ratio of mandatory prerequisites satisfied at Sim ≥ 0.75.
  2. x₂ (Preferred Skill Coverage): Ratio of preferred bonus skills satisfied at Sim ≥ 0.75.
  3. x₃ (Experience Ratio): Candidate internship months / Job required months (capped at 2.0).
  4. x₄ (Project Domain Relevance): Max cosine similarity between student projects and job domain.
  5. x₅ (Coursework Overlap): Ratio of university coursework matching job prerequisites.

5. Chapter IV: Implementation & Execution

4.1 Core Modules:

  • data_loader.py: Implements canonical alias normalization ("nlp" → "Natural Language Processing", "postgres" → "PostgreSQL").
  • semantic_matcher.py: Computes embeddings and caches vectors in an in-memory dictionary (_EMBEDDING_CACHE), cutting UI latency from 850ms to < 15ms.
  • readiness_model.py: Evaluates interview readiness via Scikit-Learn Logistic Regression and Random Forest models.
  • recommender.py: Generates targeted coursework and open-source project roadmaps for missing mandatory skills.
  • streamlit_app.py: Clean white-background interface supporting Student Dossier and Recruiter Command Center views.
def extract_features(student: dict, job: dict, match_result: dict) -> dict:
    req_cov = float(match_result.get("required_coverage", 0.0))
    pref_cov = float(match_result.get("preferred_coverage", 0.0))
    proj_rel = float(match_result.get("project_relevance", 0.0))
    exp_ratio = min(2.0, student.get("exp", 0) / max(job.get("min_exp", 1), 1))
    return {"req_cov": req_cov, "pref_cov": pref_cov, "exp_ratio": exp_ratio, "proj_rel": proj_rel}

4.2 Engineering Challenges Solved:

  • Semantic Drift: Unchecked cosine similarity scored "Python" vs. "PyTorch" at 0.58. Raising the strong threshold to 0.75 and creating the 0.55–0.74 review zone eliminated false positives.
  • UI Latency: Repeated transformer encoding caused lag. In-memory caching made subsequent lookups instantaneous.
  • Defensive Zero-Division Handling: Added safeguards for empty profiles or zero declared skills.
